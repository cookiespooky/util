# Инвентаризация страниц и компонентов

Этот документ фиксирует целевую структуру страниц перед переходом от сплошного Markdown-вывода к компонентной вёрстке.

## Типы страниц

| Тип | Назначение | Обязательные блоки | Возможные блоки |
|---|---|---|---|
| `home` | Главная и основное позиционирование | hero, services, process, request-form | selector, capabilities, facts, cities, documents, faq, cta |
| `catalog` | Каталог услуг | hero, service-grid, request-form | filters, intro, faq, cta |
| `service` | Конкретная услуга | hero, intro, process, requirements, documents, request-form | audience, categories, facts, cities, related-services, faq |
| `city` | Локальная страница подразделения | hero, contacts, service-grid, request-form | map, process, facts, documents, faq |
| `company` | Компания и инфраструктура | hero, intro, facts, capabilities, cta | timeline, geography, documents, process |
| `legal` | Лицензии и юридические материалы | hero, prose или documents | tabs, filters, faq, cta |
| `system` | Служебные страницы | hero или message | search, navigation, cta |
| `design` | Документация дизайн-системы | tokens, primitives, components | visualizations, states, examples |

## Базовые секции

### `hero`

Содержит заголовок первого уровня, лид, основные действия и необязательный визуальный компонент. Hero не формируется из DOM в браузере — он рендерится шаблоном.

### `intro`

Редакционный вводный текст ограниченной ширины. Может содержать обычный Markdown, но не управляет сеткой страницы.

### `service-grid`

Сетка карточек услуг. Источник — коллекция услуг или явно указанный набор ссылок.

### `process`

Последовательность этапов. Источник — нумерованный список или структурированные данные. Варианты: `timeline`, `route`, `compact`.

### `requirements`

Перечень данных, условий и документов, необходимых для расчёта или выполнения услуги.

### `facts`

Проверенные показатели и факты. Не публикует неподтверждённые числовые значения.

### `capabilities`

Производственная база, транспорт, оборудование и технологические возможности.

### `documents`

Лицензии, выписки, акты, формы и другие документы. Источник — коллекция или ссылки страницы.

### `cities`

Список подразделений или интерактивная карта присутствия.

### `faq`

Список пар `вопрос → ответ`, рендерится доступным аккордеоном или статичным списком.

### `cta`

Отдельный призыв к действию, не дублирующий форму без необходимости.

### `request-form`

Форма заявки с вариантом по типу страницы и услуги.

## Правила переноса контента

1. Контент не удаляется ради вёрстки.
2. Повторяемые сущности выносятся в коллекции, а не копируются по страницам.
3. Markdown описывает смысл, а не CSS-сетку.
4. Не использовать `nth-child`, `nth-of-type` и порядок соседних элементов как публичный контракт.
5. JavaScript не должен перемещать базовый контент страницы после загрузки.
6. Любой компонент должен сохранять читаемый серверный HTML без JavaScript.
7. На странице допускается один `h1`; заголовки секций начинаются с `h2`.
